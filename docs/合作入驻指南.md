# Epic Reader Extension — 合作入驻指南

> 本指南帮助第三方团队在开始扩展开发前，完成所需资源的申请和准备工作。

---

## 一、入驻清单

| # | 项目 | 提供方 | 说明 |
|---|------|--------|------|
| 1 | GitHub 仓库 | Epic | 在 `getepic-v2` 组织下创建专属仓库，用于提交扩展源码 |
| 2 | `manifest.json` | Epic | 预填好 `id` 和 `globalName` |
| 3 | API Key & Secret | Epic | 用于访问 [Open API](./open-api-book.md)（查询书籍数据、上传互动数据） |
| 4 | 书籍白名单 | Epic | 授权可访问的 `book_id` 列表 |
| 5 | 测试环境账号 | Epic | QA 阅读器（`webqa-new.getepic.dev`）的登录凭证，具有书籍订阅权限 |
| 6 | Slack 频道邀请（可选） | Epic | 共享沟通频道，用于技术交流 |

---

## 二、如何申请

通过邮件或 Slack 联系 Epic 对接人（lihaitao6@getepic.com），提供以下信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 公司名称 | 贵司/团队名称 | 好未来 |
| 产品名称 | 计划开发的扩展名称 | 星星互动扩展 |
| GitHub 账号 | 需要 fork 权限的 GitHub 账号 | `@alice`、`@bob` |
| 技术联系人 | 主要开发对接人 | alice@acme.com |
| 目标书籍 | 需要访问的书籍 ID（如已知） | 49524、49528 |

---

## 三、你将获得

申请通过后，我们会提供以下资源：

### 3.1 GitHub 仓库

- 仓库地址：`getepic-v2/extension-{公司名}-{产品名}`（如 `extension-acme-quiz`）
- 仓库中已预填 `manifest.json`，包含分配好的 `globalName`
- 你们 fork 仓库后在 fork 中开发，完成后向主仓库提交 Pull Request

### 3.2 API 凭证

- **API Key** — 放在请求头 `X-Api-Key` 中
- **API Secret** — 用于生成 HMAC-SHA256 签名
- 使用方式详见 [Open API 文档](./open-api-book.md)

> **安全提醒：** 请妥善保管 API Key 和 Secret，不要提交到源码仓库或公开分享。

### 3.3 书籍白名单

- 你的 API Key 被授权访问的 `book_id` 列表
- 后续需要新增书籍可随时联系我们

### 3.4 测试环境账号

- 地址：`https://webqa-new.getepic.dev`
- 具有书籍订阅权限的专用开发账号
- 调试流程详见[开发文档](./Epic_Reader_Extension_开发文档.md)

### 3.5 Slack 频道

- 与 Epic 团队共享的 Slack 频道，用于实时技术沟通

## 四、开发流程概览

```
1. 申请入驻（本指南）
       │
       ▼
2. 获取仓库、API 凭证、测试账号
       │
       ▼
3. Fork 仓库，开发扩展
   - 参考开发文档了解 API 用法
   - 通过 Open API 查询书籍数据、上传互动数据
   - 使用测试环境本地调试
       │
       ▼
4. 向主仓库提交 Pull Request
       │
       ▼
5. Epic 审核 → 编译构建 → 部署上线
```
